## Summary of actions

A visitor says "I'm going" through GitHub's prefilled new-file link, which writes `going/<slug>/<login>.md` directly and skips `community.py`'s refusals. `scripts/check_visitor_pr.py` (standard library only) now holds every pull request to them, reading the base and head commits through git only (`git diff --raw -z --no-renames base...head`, `git cat-file`; nothing of the PR is checked out for reading or run):

- rule 1: a PR whose author is not the repository owner changes only `going/<slug>/<author>.md` and files under `people/<author>/`; any other path fails, a deletion or rename of another member's file included. Logins compare lower-cased (GitHub logins are case-insensitive; the page lower-cases them).
- rule 2: every added or changed file under `going/` or `people/`, from anyone, is a regular file (git mode 100644: a symlink, an executable or a submodule fails), at most 2048 bytes, UTF-8, with no line `private()` refuses; a going file holds no http(s) link. `private()` mirrors `community.py`'s (email; eight digits with whitespace, dots, brackets, + or - between, whole ISO dates and clock times masked) and adds the page's copy (up to three of any non-alphanumeric between digits), both after NFKC, so a fullwidth @ or digit is the plain one. A test asserts that every sample line `community.py` refuses, the check refuses too.
- rule 3: `going/<slug>/<member>.md` has a `[a-z0-9-]+` slug that is on the head's board (the newest `events/<week>.md`, rows read as `community.py` reads them), a lower-case member name, first line `# <member> is going: <slug>`, then the board's row quoted exactly as `community.py going` writes it, then at most one note line of at most 120 characters (`going/README.md`).
- The heading and the quoted row are exempt from the privacy and link scan when they are exactly the board's and the login's text (the board's own links hold long digit runs, for example a meetup event id); so is a `people/<login>/` file's `# <login>` heading.
- rule 4: every finding is one `FAIL  rule N  <path>[:<line>]: <why>` line plus a count on stderr, exit 1; a pass is one `PASS` line, exit 0. Bad input (an empty or non-login author or owner, a commit value that starts with `-` and would be a git option) and a git failure fail closed.

The `visitor-pr` job in `.github/workflows/harness-gates.yml` runs it on `pull_request` only (never `pull_request_target`), `permissions: contents: read`, `persist-credentials: false`, no secrets; the author, owner and the two shas reach the script through `env:` and quoted shell variables, never pasted into the shell line. It runs the base branch's copy of the checker under `python -I`, so a PR cannot rewrite the rules it is judged by (the PR's own copy only while the base has none).
